## 调研方法

使用 cloud-help-docs 官方资料检索流程。IQS 首次请求因网络解析失败，转用网页搜索与原文读取。阿里云采用中国站；Google Cloud、Microsoft Azure、AWS 全球文档用于通用工程机制参考，不推导其中国区可用性；NIST、ISO、OpenLineage、TensorFlow、Feast、Hugging Face、MLflow、OpenTelemetry 为机构或项目公共文档；中国法规使用国家网信办原文。

来源清单及论据边界见同目录 `ai-expansion-sources-2026-10-04.json`。只保留来源元数据与核验结论，不复制完整网页。每篇文章在关键事实附近给出直接链接，文末登记访问日期与站点。

## 核验结论与写作约束

1. OpenLineage 的 Dataset / Job / Run 与 ML Metadata 的制品 / 执行关系说明血缘模型；具体数据契约、清单字段和恢复流程为本站工程建议。
2. 数据集管理记录与底层字节冻结分开。PAI 文档用于证明其数据集版本与存储入口，不据此推断所有底层文件不可变。
3. Feast 时点关联需要检查事件时间和数据实际可用时间；当前文档的 created timestamp 过滤有后端支持限制，不给所有版本通用的 API 承诺。
4. MLflow 提示词模板版本不可变，但别名和关联模型配置可变；联合发布清单应独立冻结实际配置。避免把固定提示词版本写成完整复现保证。
5. Azure AI Search 权限方案分别注明应用安全过滤和原生预览功能；源删除可能留下索引孤儿，恢复旧索引还要重新应用撤销记录。
6. Google MLOps 的主要适用范围为预测型 AI；生成式应用的资产与流程同时对照 Microsoft GenAIOps 文档。持续训练不等于无条件自动上线。
7. OpenTelemetry GenAI 旧规范入口已迁移到官方独立仓库，记录入口变化；不把未逐项核验的字段标成稳定标准。遥测正文采集遵循最小化。
8. NIST AI RMF 采用 1.0（2023）框架及 2024 生成式 AI Profile；官网提示 1.0 正在修订。ISO/IEC 42001:2023 只读取公开概览，不声称已核验付费标准全文或提供认证结论。
9. 法规仅解释已读取原文的适用入口，分别注明公众服务范围与生成合成内容标识，不将其表述为完整法律清单。风险等级、责任表和验收表均为工程设计建议。
10. 案例是虚构场景与待执行验证方案，不写成已完成的生产实验；阈值按业务基线制定，不提供无依据的通用百分比。
