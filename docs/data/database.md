## 要点提纲

### 1. 选型四问

1. **访问模式**：点查/范围查/聚合分析？读写比？
2. **一致性要求**：强一致 / 最终一致可接受窗口？
3. **规模与增长**：单表量级、QPS、三年后数据量？
4. **运维与成本**：团队能力、预算、容灾要求？

### 2. 关系型：RDS 与云原生数据库

- RDS（MySQL/PG）：最稳的默认选择，重点在参数调优与备份策略
- 云原生数据库（PolarDB 类）：计算存储分离，读副本秒级扩展
- 自建 vs 托管的决策点：人力成本、版本控制需求、合规

### 3. 缓存与 NoSQL

- Redis：缓存、分布式锁、排行榜；注意大 Key 与热 Key
- 文档/宽表（MongoDB 类 / Tablestore 类）：Schema 灵活、海量写入
- 时序数据库：监控与 IoT 场景的专用答案

### 4. 规模化的两条路

- **垂直**：更强的实例 + 读写分离（读多写少）
- **水平**：分库分表（中间件）→ 分布式数据库（NewSQL 类）
- 经验：能不拆就不拆；要拆先拆"读"，再拆"写"

### 5. 数据迁移

- DTS 类工具：全量 + 增量 + 校验三段式
- 双写灰度与回滚预案：迁移的本质是"可逆的状态机推进"
