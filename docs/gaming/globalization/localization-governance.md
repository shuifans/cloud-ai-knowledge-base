# 出海、本地化与合规协作

> 面向游戏市场进入与技术方案协作。本文提供业务、内容和系统的核查框架，具体法律义务及平台要求由相应责任人按目标市场和上线时间确认。

## 市场、语言、平台与部署地区分别管理

目标市场涉及用户、发行与经营；语言涉及文本、音频和支持；平台涉及接入与分发；部署地区涉及网络、数据和资源。这些维度相关，但不能彼此替代。用户所在国家不必然等于其语言偏好，也不必然等于账号所属区或服务部署地区。

Steam 文档区分商店页面本地化与游戏内本地化，并分别描述界面、字幕和完整音频支持。由此可见，商店页翻译完成并不能证明游戏内体验已经本地化。[Steam 本地化](https://partner.steamgames.com/doc/store/localization)

| 工作流 | 需要交付什么 | 主要责任与协作 |
| --- | --- | --- |
| 市场与发行准备 | 用户假设、平台范围、合作与上线计划 | 发行、商务、制作人 |
| 内容本地化 | 术语、上下文、文本、音频、字体及素材版本 | 本地化、叙事、主美、研发 |
| 支付与权益 | 商品、币种、渠道、到账、退款和客服规则 | 商务、财务、研发、客服 |
| 服务与支持 | 地区路由、时区、值守和玩家沟通 | 平台、运维、运营、客服 |
| 法规与平台核查 | 适用主体、数据、内容、年龄与授权要求 | 法务、发行、隐私和安全负责人 |
| 上线验收 | 目标语言、设备、网络和用户路径证据 | QA 与各责任团队 |

## 本地化要进入实际游戏验收

建议以稳定文本标识连接原文、上下文、翻译和版本，而不是只给翻译团队一列孤立字符串。角色身份、情境、性别或语法变量、字数约束和占位符含义应一同交接。

**语言质量验证（LQA）** 关注译文、术语和上下文；功能测试关注语言切换、显示、输入、存档和购买等行为。二者需结合：翻译正确的文字仍可能被裁切，长语言或从右到左的布局也可能改变交互。

~~~mermaid
flowchart TD
  A["确定市场、语言、平台与经营主体"] --> B["分配内容、系统和合规责任"]
  B --> C["制作本地化版本并核验目标要求"]
  C --> D["在目标设备与网络验证玩家路径"]
  D --> E{"内容、服务和适用要求均有证据吗"}
  E -->|否| F["修复缺口并更新范围或排期"]
  F --> C
  E -->|是| G["按地区与版本发布"]
  G --> H["跟踪反馈、规则变化与持续支持"]
~~~

配音需明确演员或素材授权、角色语气、发音、时长和字幕同步。AI 翻译与合成语音可以作为候选工作流，但需按同样的内容、权利与游戏内验收要求评估。

## 合规核查应产出可落实的工程要求

下面是问题清单，不是所有市场的完整法规结论。每项应记录目标地区、适用主体、来源、生效日期、核验日期、负责人与落实证据。

| 主题 | 需要确认的问题 | 可能涉及的工程交接 |
| --- | --- | --- |
| 出版、发行与平台准入 | 哪个主体负责，适用什么许可、审核或认证 | 材料、构建版本、地区开放与发布门禁 |
| 年龄与未成年人保护 | 年龄识别、服务限制和监护相关要求是什么 | 登录、权限、时段、付费及异常处理 |
| 隐私与数据流转 | 收集什么、为何收集、给谁、保存多久、如何响应权利请求 | 数据目录、SDK、访问、保留、删除与审计 |
| 虚拟商品与消费者权益 | 商品说明、退款、随机机制等适用规则是什么 | 交易记录、说明展示、发货与纠纷处理 |
| 玩家内容与社区治理 | 谁审核、怎样举报、申诉与处理 | 队列、规则、操作记录和复核 |
| 资产、音乐与 AI 素材授权 | 是否有目标用途、地区和期限的使用权 | 资产来源、合同记录、使用范围追踪 |

中国境内网络游戏的核查可从国家新闻出版署公开文件入手。例如其 2021 年通知涉及未成年人服务时间及实名注册登录要求。这里引用该文件说明会影响账号与服务流程的要求类型，不代表已经核对全部后续规范或具体项目适用性。[国家新闻出版署通知](https://www.nppa.gov.cn/xxfb/tzgs/202108/t20210830_666285.html)

欧盟委员会关于隐私设计的说明强调在处理活动设计之初考虑技术与组织措施。工程上应把最小化、访问和保留要求转成具体系统行为；是否适用及如何落实，需结合处理活动与法律评估。[欧盟委员会：数据保护义务](https://commission.europa.eu/law/law-topic/data-protection/information-business-and-organisations/obligations_en)

## 跨地域架构不能只看“最近的机房”

需要一同考虑玩家实际网络、匹配池规模、朋友关系、数据读写、故障域、运维支持和数据流转。单纯增加地域可能缩小每个匹配池或增加跨区状态同步，具体收益应通过目标路径验证。

活动时间建议保存统一的时间基准并按明确地区展示，处理夏令时与跨日边界。支付币种、展示价格和财务结算也应分别建模；不要把字符串翻译后的价格直接当成可结算金额。

常见漏项包括只翻正文没有翻图片内文字、字幕与配音版本错配、海外客服无法访问必要知识、删除请求遗漏分析副本，以及供应商素材授权没有覆盖目标用途。上线清单应把这些交接落到具体负责人。
