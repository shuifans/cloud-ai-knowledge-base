# 游戏 AI 场景与验收方法

> 面向游戏 AI 方案调研与落地评估。本文从岗位的真实工作拆解场景，定义输入、可用结果和验收责任，不以演示效果或生成速度代替业务收益。

## 先找一个能完整验收的工作单元

“美术 AI”“运营 Agent”仍然过于宽泛。可进一步定义为：为一种资产生成可供主美筛选的候选方案、根据已批准知识回答某类客服问题、检查某组活动配置的冲突。每个工作单元都要有真实输入、使用者和失败处置。

以下列出候选场景，不表示某个模型已经达到生产要求。

| 场景与主要使用者 | 输入与期望交付 | 验收关注 | 需要保留的人工责任 |
| --- | --- | --- | --- |
| 策划与配置辅助 | 规则、历史版本、字段约束 → 检索、冲突提示与测试草案 | 可追溯、遗漏和错误提示、规则覆盖 | 设计目标与最终规则 |
| 美术与素材制作 | 风格、任务和资产约束 → 候选素材或处理结果 | 可用率、风格、修改与下游制作成本 | 艺术方向、来源与最终入库 |
| 代码与测试 | 代码、接口、缺陷和环境 → 修改建议、用例或复现线索 | 行为正确性、回归、安全与维护 | 审查、测试与发布 |
| 本地化与配音 | 上下文、术语、角色、授权 → 翻译或音频草稿 | 术语、语气、长度、占位符和游戏内效果 | 母语审校、授权和内容审核 |
| 客服知识助手 | 有权限且在有效期内的知识 → 带依据的答复 | 事实正确、拒答、转人工、问题解决 | 高风险操作与争议处理 |
| 运营与舆情分析 | 定义清楚的数据或反馈 → 聚类、摘要和解释候选 | 样本偏差、引用、漏报与误报 | 原因判断和运营行动 |
| NPC 与交互内容 | 角色设定、状态和玩家输入 → 受约束的交互 | 角色一致性、延迟、成本、可控行为 | 游戏规则、资产操作与内容治理 |
| 企业知识与协作 | 授权文档和工作流 → 检索与受限任务执行 | 权限、版本、审计、撤销和恢复 | 业务决策和工具授权 |

## 沿原流程测量，而不是只测模型输出

以虚构的角色概念探索为例，需要记录需求整理、生成等待、筛选、修改、下游建模参考和验收。某张图视觉上好看，不代表其结构足以支持三维制作；Epic 的内容导入文档也展示了运行资产还涉及网格、材质和动画等独立对象。[资产导入边界](https://dev.epicgames.com/documentation/unreal-engine/fbx-content-pipeline?lang=en-US)

~~~mermaid
flowchart TD
  A["定义工作单元、数据权限和验收者"] --> B["采集原流程基线与代表任务"]
  B --> C["在相同要求下运行候选工作流"]
  C --> D["记录成功、失败、人工复核与返工"]
  D --> E{"质量与业务约束均满足吗"}
  E -->|否| F["调整场景或停止试点"]
  E -->|是| G{"总成本及交付周期改善吗"}
  G -->|否| H["分析等待、集成和维护代价"]
  G -->|是| I["小范围接入并持续复核"]
  I --> J["模型、数据或规则变化触发回归"]
~~~

## 试点至少保留三层指标

**模型层**看生成质量、正确性和延迟；**工作流层**看合格交付、返工、等待与总工时；**业务层**看项目实际关心的内容供给、服务质量或经营结果。前一层改善不自动证明后一层改善。

建议按任务复杂度和语言等因素分层取样，使用相同验收标准比较。保留失败样本，避免只筛选最佳输出；验收者可在条件允许时不知道结果来自哪种流程，以减少偏好影响。

~~~text
单位合格交付成本
=（模型或算力 + 人工操作与复核 + 返工 + 集成维护分摊）
  / 通过最终验收的交付数量
~~~

交付数量为零时该指标不可定义，应报告失败与投入。人工节省需按实际任务时间测量；如果释放的时间未改变人员支出或产能，不能直接宣称实现等额现金节省。

| 场景 | 比演示数量更有意义的证据 |
| --- | --- |
| 素材辅助 | 最终可用率、修改工时、下游返工和同类任务周期 |
| 客服助手 | 正确解决、重开、转人工、引用正确性与权限测试 |
| 代码辅助 | 合并后行为、测试与缺陷、维护工作量 |
| NPC | 长对话稳定性、角色约束、端到端时延和玩家体验 |
| 分析助手 | 指标口径一致、可重算、事实与假设区分 |

## 数据、权限与运行方式共同决定部署

先盘点未发布资产、源代码、玩家信息和合作素材的使用范围，再讨论托管 API、专有部署或本地运行。部署位置本身不能替代访问权限、日志管理、来源和删除机制。

NIST 的生成式 AI Profile 是面向跨行业风险识别与管理的框架，可帮助组织风险讨论；它不是游戏生产合格证明或某个模型的能力认证。[NIST 生成式 AI Profile](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence)

对可执行工具的助手，应限定资源和动作、验证输入并保留审计。玩家文本、工单及检索材料应作为待处理数据；不能让其中的指令越过系统权限。涉及发奖、退款、封禁和生产配置的动作需要明确授权规则与失败恢复。

## 进入生产需要什么证据

建议保留任务集与评审记录、成本计算、数据权限、接口与责任、降级路径、版本和回归条件。超时、限流、模型不可用或知识过期时，应有可用的人工或确定性流程。

NPC 推理成本还需区分潜在玩家数、实际触发比例、对话频率、上下文长度与并发；美术批任务则可能更关注排队与吞吐。二者不能用同一份“每用户 token 预算”直接估算。
