# Agent 与 MCP

## 要点提纲

### 1. 从 Copilot 到 Agent 的分级

- **L1 对话**：问答与生成，无外部动作
- **L2 工具调用**：Function Calling，模型决定调什么工具
- **L3 工作流**：多步规划 + 工具编排（ReAct 模式、Plan-and-Execute）
- **L4 自主体**：长任务、自我反思、多 Agent 协作——目前落地仍需谨慎

### 2. Function Calling 的工程要点

- 工具描述（Schema）就是 Prompt：描述质量直接决定调用准确率
- 参数校验与幂等：模型会幻觉出不存在的参数值
- 失败处理：工具报错要"可被模型理解"，否则陷入重试死循环

### 3. MCP（Model Context Protocol）

- 解决的问题：工具接入标准化，"一次接入、处处可用"
- 架构角色：Host / Client / Server，传输层与能力协商
- 实践观察：生态扩张速度快，但安全（工具越权、提示注入）仍是落地首要门槛

### 4. Agent 应用的架构模式

- 单 Agent + 工具箱：覆盖 80% 场景，先做这个
- 路由 + 专家 Agent：意图分发，各域独立迭代
- 多 Agent 协作：复杂任务分解——注意协作开销可能大于收益
- 人机协同点：高风险动作必须保留人工确认

### 5. 评估与上线

- Agent 评估比单轮问答难一个量级：端到端任务成功率、步数、成本
- 上线清单：动作白名单、预算上限（token/调用次数）、审计日志、回滚路径
