## 要点提纲

### 1. 三支柱的定位

| 支柱 | 回答的问题 | 典型工具 |
| --- | --- | --- |
| 指标 Metrics | 系统现在怎么样？（趋势/告警） | Prometheus / 云监控 |
| 日志 Logs | 刚才发生了什么？（细节取证） | SLS / ELK |
| 链路 Tracing | 慢/错在哪一环？（跨服务定位） | OpenTelemetry / Jaeger 类 |

- 三者必须通过统一标签（服务名、实例、TraceID）打通，否则是三个孤岛

### 2. 指标工程

- USE / RED 方法论：资源视角（利用率/饱和度/错误）与服务视角（请求率/错误率/时延）
- 告警分级：P0 电话、P1 群通知、P2 日报——告警疲劳是体系失败的第一信号
- SLI/SLO：从"监控指标"到"服务承诺"的跃迁

### 3. 日志工程

- 结构化日志（JSON）+ 统一采集：排障效率的分水岭
- 采样与成本的平衡：全量存不起，全丢找不到
- 日志与 Trace 的关联：TraceID 贯穿是基本要求

### 4. 云上的可观测

- 托管服务的好处：免运维 + 与云产品深度集成（K8s、RDS、网关的现成大盘）
- 自建与托管混用：核心指标托管化，业务指标自建

### 5. 从可观测到稳定性运营

- 故障响应流程：发现 → 止血 → 定位 → 复盘（止血永远优先于定位）
- 混沌工程/演练：在可控环境注入故障，验证监控告警链路本身
