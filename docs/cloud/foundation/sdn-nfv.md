# SDN / NFV

## 要点提纲

### 1. 传统网络的痛点

- 控制逻辑固化在设备中，策略变更依赖逐台配置
- 网络能力（防火墙、LB、NAT）依赖专用设备 → 采购周期长
- 云的需求：网络要能随 API 一起"被创建"

### 2. SDN：控制面与数据面分离

- 三层架构：应用平面 / 控制平面 / 数据平面
- 南向接口（OpenFlow 等）与北向 API
- 云内实现：集中式控制器 + 宿主机 vSwitch（OVS）下发流表
- VPC 的本质：用 VXLAN/Geneve 隧道 + 流表，在物理网络上"虚拟"出隔离网络

### 3. NFV：网络功能虚拟化

- 用通用服务器 + 软件替代专用网络设备（vFirewall、vLB、vRouter）
- 云上的形态：负载均衡、NAT 网关、弹性公网网关都是 NFV 思想的产品化
- 性能演进：DPDK、智能网卡 / DPU 卸载数据面

### 4. 从私有云到公有云的网络演进

- OpenStack Neutron 的 ML2 插件体系
- 大规模网关集群：ECMP、一致性哈希、会话保持
- 混合云：专线（物理）+ VPN（加密隧道）+ CEN 类全球骨干

### 5. 实践观点

- 用户不需要理解 SDN，但需要理解 VPC 的三个抽象：**地址空间、路由、安全组**
- 网络规划错误是最难回滚的上云错误，先规划后建设
