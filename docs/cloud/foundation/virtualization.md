# 虚拟化与 KVM

## 要点提纲

### 1. 为什么需要虚拟化

- 硬件利用率矛盾：单应用独占物理机 → 资源碎片化
- 隔离性需求：多租户、安全边界
- 弹性供给的前提：把"机器"变成可编排的资源单元

### 2. 虚拟化技术路线

- **全虚拟化**：Hypervisor（Type-1 裸金属 / Type-2 宿主）
- **半虚拟化**：Guest 感知虚拟化（virtio 驱动）
- **硬件辅助虚拟化**：Intel VT-x / AMD-V、EPT/NPT 内存虚拟化
- KVM 的定位：Linux 内核模块 + QEMU 用户态，"内核即 Hypervisor"

### 3. KVM/QEMU 架构

- KVM 负责 CPU/内存虚拟化（`/dev/kvm`）
- QEMU 负责设备模拟与 IO 路径
- IO 虚拟化演进：设备模拟 → virtio → vhost / SR-IOV 直通
- 性能开销来源与典型压测数据（CPU <5%，IO 差距可达数倍）

### 4. 与容器的对比

| 维度 | 虚拟机 | 容器 |
| --- | --- | --- |
| 隔离级别 | 硬件级（独立内核） | 进程级（共享内核） |
| 启动速度 | 分钟级 | 秒级 |
| 密度 | 低 | 高 |
| 适用 | 强隔离、异构内核 | 微服务、弹性伸缩 |

- 实践观点：不是替代关系，而是"安全容器"（如 Kata）在两者之间融合

### 5. 云场景下的虚拟化

- 大规模宿主机管理：热迁移、动态资源调整
- 裸金属（神龙类架构）：虚拟化开销下沉到硬件，"云的弹性 + 物理机性能"
- GPU 虚拟化：vGPU、MIG 与直通的选择
