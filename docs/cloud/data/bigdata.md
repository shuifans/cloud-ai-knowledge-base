## 要点提纲

### 1. 数据平台分层

- **采集**：日志（SLS/Flume 类）、业务库 CDC（DTS/Canal 类）、埋点
- **存储**：对象存储打底 + 湖格式（Iceberg/Hudi/Paimon 类）
- **计算**：离线批（MaxCompute/Spark 类）+ 实时流（Flink 类）
- **服务**：OLAP 引擎直接服务报表/大屏/分析

### 2. 离线数仓

- 分层建模：ODS → DWD → DWS → ADS，维度建模（Kimball）仍是主流
- Serverless 化的趋势：存算分离、按作业计费
- 成本治理：存储生命周期 + 计算配额 + 作业巡检（跑批时间是第一指标）

### 3. 实时计算

- Flink 生态的统治地位与原因（状态管理、Exactly-Once、低延迟）
- 实时数仓的代价：链路长、一致性难、运维重——先问"真的需要多实时"
- 秒级/分钟级/小时级的成本差异通常是数量级的

### 4. 湖仓一体

- 动机：一份数据同时服务批与流，避免"湖一套、仓一套"
- 落地关键：统一元数据、开放表格式、引擎兼容性
- 现实：多数团队仍在"湖 + 仓"双轨，一体化是渐进过程

### 5. 检索与向量

- Elasticsearch：日志检索、全文搜索的事实标准
- 向量检索：大模型时代的"新大数据"，见 [RAG 架构设计](/ai/application/rag-architecture)
