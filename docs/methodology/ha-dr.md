# 高可用与容灾设计

## 要点提纲

### 1. SLA 的数学

- 99.9%（8.8h/年）→ 99.99%（52min/年）：每多一个 9，成本非线性上升
- 串联系统的可用性 = 各环节乘积：依赖越多，目标要定得越高
- 原则：可用性目标由业务损失倒推，而不是技术能力正推

### 2. 容灾分级

| 级别 | 形态 | RPO/RTO | 成本 |
| --- | --- | --- | --- |
| 1 | 数据备份 | 小时级 | 低 |
| 2 | 同城双活（同地域多可用区） | 分钟级 | 中 |
| 3 | 异地灾备（冷/温备） | 小时级 | 中 |
| 4 | 异地多活（单元化） | 秒级 | 高 |

- 多数业务的合理答案：多可用区双活 + 异地数据备份，而非追求多活

### 3. 多可用区设计

- 可用区 = 独立故障域（电力/网络/物理隔离）
- 应用层：跨 AZ 部署 + 负载均衡
- 数据层：同城多副本（RDS/PolarDB 高可用版、OSS 同城冗余）
- 注意"伪多可用区"：依赖了单 AZ 的中间件就前功尽弃

### 4. 异地多活的门槛

- 数据同步延迟是物理约束：1000km ≈ 5ms 单向
- 单元化：按用户维度切流，单元内闭环
- 适用判断：真正的全国性业务 + 强监管/强品牌要求，否则性价比存疑

### 5. 容灾演练

- 备份不演练 = 没有备份；切换不演练 = 不敢切换
- 演练三层次：桌面推演 → 数据恢复验证 → 真实切换（含回切）
- 故障注入与混沌工程：把演练常态化
